# 割り勘くん 簡易レポート

## 作品名
割り勘くん

## 作品概要
Slack 上で行う共同購入において、希望数の集計、送金依頼、支払い確認、主催者への購入催促を自動化するバックグラウンド処理システムを制作した。  
本作品では、JavaScript を用いた n8n のワークフロー処理を中心に、Slack、Google Sheets、Webhook を連携させている。

## 解決したい課題
共同購入では、主催者が希望者ごとの個数や支払い状況を追跡し続ける必要があり、少人数でも運用コストが高くなる。  
特に以下の点が課題だと考えた。

- 希望者ごとの数量集計が手作業になる
- 送金依頼を個別に送る必要がある
- 誰が支払い済みかを把握しづらい
- 全員の支払い完了後に主催者へ購入依頼する流れが煩雑になる

## 提案した解決策
新しい UI を増やすのではなく、普段使っている Slack 上で処理を完結させる方針を取った。  
そのために、n8n をハブとして次の処理を構成した。

1. Slack の入力内容を受け取る
2. JavaScript で管理ID・希望者管理IDを生成し、希望者ごとのデータに展開する
3. Google Sheets にステータスを保存する
4. 希望者へ送金依頼DMを送る
5. 送金済みボタンの Webhook を受け取り、支払い完了を反映する
6. 全員完了時に主催者へ購入催促DMを送る

## 使用技術
- JavaScript
- n8n
- Slack API
- Webhook
- Google Sheets
- GitHub Pages

## 工夫した点
- 行番号ではなく、`管理ID` と `希望者管理ID` を用いてデータを識別する設計にした
- Google Sheets 上でステータス管理を行い、再送や誤更新を防ぎやすくした
- Slack 上で送金確認まで完結するようにし、利用者の操作を最小限にした
- 主催者用と希望者用で処理を分け、必要な相手にのみ通知するようにした

## 苦労した点
- n8n の Loop や Merge の挙動により、入力データの整合性を保つのが難しかった
- Slack API の DM 送信や権限設定の調整に時間がかかった
- スレッドタイムスタンプとコメントタイムスタンプを混同しないように設計を見直した
- Google Sheets を安全に更新するために、行番号依存の方法から識別子ベースの方法へ変更した

## 今後の改善点
- 超過注文時の処理を追加し、例外時の対応を完成させる
- LINE や Discord にも対応できるようにする
- PayPay API を用いた自動集金確認や、将来的な自動集金システムへ発展させる
- 最終的には自動発注まで含めた共同購入支援システムに拡張する
