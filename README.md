# Warikan-kun

Warikan-kun は、LINE グループの共同購入を、募集・応募・支払い案内までできるだけ少ない操作で回すためのサービスです。

原点は単純です。

**人は快適さ、楽さに対価を喜んで支払う。だから Warikan-kun は手軽さの UX を最大化する。**

共同購入の本当の面倒は、割り勘計算そのものではありません。募集を作ること、参加意思を集めること、数量を聞くこと、支払いを案内すること、未払いを催促すること、グループの空気を悪くしないことです。

Warikan-kun は、その面倒を消すためにあります。

## 原点

このプロジェクトは、単なる便利ツールではありません。

短期的には、学生グループの日常導線で共同購入を回すための LINE ツールです。中期的には、グループ単位の購買を支えるコマース基盤です。長期的には、資本を作り、新しいビジネスへ進むための足がかりです。

目指すのは、最初から巨大なアプリを作ることではありません。

まず、目の前の学生グループで本当に使われること。主催者がもう一度使いたいと思うこと。参加者が考えずに応募できること。支払いと催促が気まずくならずに進むこと。

その積み重ねで GMV を作り、会社価値を作り、次の挑戦に進みます。

長期の夢は、得た資本でマイニングファームのようなデジタルインフラ事業を持つことです。そのためにも、Warikan-kun ではユーザー導線、決済、キャッシュフロー、監視、障害対応、法務・会計、不正対策を現実の事業として学びます。

## UX 原則

Warikan-kun の競争力は機能数ではなく、手軽さです。

- 主催者は募集を投げるだけ
- 参加者は欲しい数を押すだけ
- 応募まではグループ内で完結
- 支払い、催促、証跡、完了通知は 1:1 DM へ分離
- 案件IDを参加者に手入力させない
- 迷う画面を作らない
- 1画面1主行動にする
- 失敗しても戻れるようにする

最高の参加者体験はこれです。

```text
グループに募集が流れる
↓
「欲しい」を押す
↓
「1個 / 2個 / 3個 / その他」を選ぶ
↓
応募済み
```

最高の主催者体験はこれです。

```text
商品名
金額
個数
締切
作成
```

検索、詳細設定、PayPay ID、補足文は補助です。主導線を邪魔してはいけません。

## LINE を選ぶ理由

LINE が好きかどうかは関係ありません。

学生グループの現実は LINE にあります。ユーザーは新しいアプリを入れたくないし、ログインもしたくないし、案件IDも打ちたくありません。グループに流れてきたメッセージのボタンを押して終わりにしたい。

だから Warikan-kun は LINE を入口にします。

これは妥協ではなく、事業判断です。

```text
自分の好み < ユーザーの日常導線
理想のアプリ < 既に使われている場所
作りたいもの < 使われるもの
```

## 事業仮説

人がお金を払うのは、機能そのものではなく、面倒が消えることに対してです。

- 考えなくていい
- 説明しなくていい
- 催促しなくていい
- 間違えなくていい
- 気まずくならない
- すぐ終わる

最初に売るものは「機能」ではありません。

**主催者の面倒を消す権利**です。

初期は無料で使われることを優先します。PMF が見えたら主催者向け便利機能、決済導入後は GMV 手数料、大規模化後は団体・グループ向け管理機能へ広げます。

## 開発メモ

- `line-liff/assets/config.js` は実運用値を入れる設定ファイルです
- Apply 画面は `apply.html?managementId=...` のリンク起動前提です
- 通常の `1個 / 2個 / 3個` 応募は LINE グループ内のボタンで完了させます
- `募集を開始する` は bot のグループ投稿成功までを完了条件にします
- 投稿成功後は完了画面を5秒だけ表示し、LIFFを閉じてLINEへ戻します
- 投稿失敗時は手動共有ではなく再試行を主導線にします
- 参加者に案件ID手入力を要求しません
- write request には `idempotencyKey` を付けます
- `.swp` や `.DS_Store` は `.gitignore` で除外しています
